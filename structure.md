# Техническое задание: PWA «Медитация с Шри Шри Рави Шанкаром»

## 1. Общее описание и цели

### 1.1. Название и тип приложения

- Рабочее название: **«Meditate with Sri Sri»** (локализуемо как «Медитация с Шри Шри»).
- Тип: **прогрессивное веб-приложение (PWA)**, работающее в браузере и устанавливаемое на устройство (иконка на домашнем экране, полноэкранный режим, офлайн‑поддержка).[web:16][web:18][web:19][web:20][web:3  

### 1.2. Основная идея

- Минималистичное, спокойное приложение для медитации с Шри Шри Рави Шанкаром.
- Ключевые элементы:
  - Приветственная видеозаставка: Шри Шри приветствует пользователя, машет рукой, приглашает присесть.
  - Экран выбора практики: фон — видео прогулки вдоль Ганги.
  - Экран сессии: фон — видео, где Шри Шри сидит на берегу Ганги или моря.
- Режимы практики:
  - **Guided** — аудио/видео управляемые медитации с голосом Шри Шри.
  - **Silent/Custom** — собственный настраиваемый таймер без контента (или с пользовательским треком в будущем).[web:22][web:25][web:28]

### 1.3. Цели продукта

- Обеспечить **максимально простой путь** к медитации: минимум кликов, минимум настроек.
- Делать акцент на **спокойствии и погружении**, а не на «функциональном перегрузе».
- Обеспечить **нативный UX**:
  - установка приложения (Add to Home Screen),
  - полноэкранный режим,
  - работа без сети (офлайн‑медитации).[web:18][web:19]

### 1.4. Правовые и контент‑ограничения

- Использование имени, образа и официальных материалов Шри Шри требует **письменного разрешения** от правобладателей (Art of Living Foundation и другие организации).
- На этапе прототипирования:
  - использовать нейтральные заглушки (абстрактное видео/силуэты),
  - не использовать реальные видео/аудио с Шри Шри без прав.

## 2. Целевая аудитория и сценарии использования

### 2.1. Целевая аудитория

- Люди, интересующиеся медитацией и/или Шри Шри Рави Шанкаром.
- Возраст: примерно 20–60 лет.
- Основное устройство: смартфон (iOS/Android), вторично — десктоп.[web:22][web:25][web:28]
- Особенности:
  - не хотят сложных настроек,
  - ценят мягкий, ненавязчивый опыт.

### 2.2. Основные сценарии

1. **Быстрый старт медитации**
   - Открытие приложения → приветствие → 1–2 клика → медитация уже запущена.
2. **Выбор guided‑медитации по длительности**
   - Пользователь выбирает, например, «15 минут» → видит 1–3 релевантные медитации → запускает.
3. **Своя практика с таймером**
   - Выбор «Своя практика» → выбор длительности → запуск таймера с фоновым видео.
4. **Офлайн‑медитация**
   - Приложение и базовый набор медитаций уже кешированы → пользователь без интернета может:
     - запустить одну из заранее закешированных guided‑медитаций,
     - или воспользоваться чистым таймером.[web:18][web:21][web:27]

## 3. Концепция UX и визуальный стиль

### 3.1. UX‑принципы

- **Меньше выбора — меньше тревоги**:
  - не показывать длинные списки медитаций,
  - максимум 3–5 опций на экране.[web:22][web:25][web:28]
- **Линейный поток**:
  - приветствие → выбор → сессия → мягкий экран завершения.
- **Минимум действий**:
  - один тап для старта,
  - один тап для паузы,
  - один тап для скрытия/показа UI во время сессии.
- **Фокус на практике**:
  - UI «растворяется», основное внимание — на фоне и внутреннем состоянии пользователя.

### 3.2. Визуальный стиль

- Цветовая палитра:
  - тёплые нейтральные фоны (бежевые/песочные),
  - акценты — мягкие цвета воды Ганги/моря (голубые, бирюзовые, зелёно‑голубые).[web:22]
- Типографика:
  - спокойный sans‑serif для текста,
  - возможно, лёгкий serif для заголовков.
- Формы:
  - округлённые углы,
  - мягкие тени,
  - отсутствие резких контрастов.
- Фоновые видео:
  - медленные, плавные, без ярких вспышек и резких движений, чтобы не мешать медитации.[web:12]

## 4. Структура экранов и навигация

### 4.1. Карта экранов

1. **Splash / Loading**
   - Логотип приложения.
   - Короткий fade‑in, затем переход на приветственный экран.

2. **Приветственный экран (Welcome)**
   - Фон: короткое приветственное видео (без звука).
   - Текст: «Намасте, давайте сядем для медитации» (варианты текста в локализациях).
   - Основная кнопка: «Начать медитацию».
   - Небольшой дисклеймер о том, что приложение не заменяет медицинскую помощь.

3. **Экран выбора практики (Meditation Picker)**
   - Фон: видео прогулки вдоль Ганги, затемнённое/размытое для читаемости текста.
   - Блоки:
     - «Видео‑медитации» (опционально, по мере наличия контента).
     - «Аудио‑медитации».
     - «Своя практика» (таймер).
   - Элемент списка (карточка медитации):
     - название,
     - длительность,
     - краткое описание (1 строка).

4. **Экран guided‑сессии (Session: Guided)**
   - Фон: видео, где Шри Шри сидит на берегу Ганги/моря.
   - В центре:
     - название медитации,
     - прогресс: «прошло / осталось».
   - Контролы:
     - Play/Pause,
     - опционально перемотка ±10–15 секунд,
     - регулировка громкости.
   - Режим «фокус»:
     - один тап скрывает весь UI, остаётся только видео и/или небольшой таймер.

5. **Экран таймера (Session: Timer‑only)**
   - Фон: то же видео или статичный кадр воды.
   - Крупный круговой таймер.
   - Пресеты длительности: 5 / 10 / 20 / 40 минут + кастомный ввод.
   - Звуковой сигнал (колокол/гонг) в конце.

6. **Экран завершения (Session End)**
   - Сообщение: «Практика завершена. Как вы себя чувствуете?».
   - Возможный блок настроения (3–5 иконок/эмодзи).
   - Кнопки: «Ещё одна медитация» / «Завершить».

### 4.2. Навигация

- Приложение — SPA с внутренним роутингом:
  - `/welcome` → `/picker` → `/session` → `/end`.
- Back‑навигация:
  - стрелка назад на большинстве экранов,
  - при выходе из сессии — подтверждение («Завершить медитацию?»).

## 5. Функциональные требования

### 5.1. PWA‑функциональность

1. **Манифест**
   - Файл `manifest.webmanifest` включает:
     - `name`, `short_name`,
     - `start_url`,
     - `display: "standalone"`,
     - `background_color`, `theme_color`,
     - набор иконок (192×192, 512×512 и др.).[web:16][web:18][web:19][web:20][web:30]
   - Приложение должно быть «устанавливаемым» (Add to Home Screen).[web:18][web:19]

2. **Service Worker и офлайн‑поддержка**
   - Регистрация сервис‑воркера в JS‑коде (не через манифест).[web:21][web:24][web:27]
   - В `install`‑событии:
     - кешировать application shell (HTML, CSS, JS, иконки),
     - кешировать базовый набор аудио/видео для офлайн‑медитации.[web:18][web:20][web:21]
   - В `activate`:
     - очистка устаревших кешей.
   - В `fetch`:
     - стратегия `Cache First` или `Stale-While-Revalidate` для статики,
     - `Stale-While-Revalidate` или `Network First` с fallback для медиа‑файлов.[web:18][web:21][web:27]
   - При отсутствии сети для незакешированного ресурса — показать дружелюбное offline‑сообщение и предложить таймер.

3. **Безопасность**
   - Приложение должно работать по **HTTPS** (обязательно для service worker).[web:20][web:27][web:30]

### 5.2. Аудиоплеер

- Поддерживаемые форматы: минимум `mp3` (опционально `aac`, `ogg`, `m4a`).
- Функции:
  - Play/Pause.
  - Отображение текущего времени и общей длительности.
  - Возможная перемотка ±10–15 секунд.
- Поведение:
  - сохранение прогресса при сворачивании вкладки (в пределах одной сессии),
  - попытка поддерживать фоновое воспроизведение (ограничения браузеров – учесть).

### 5.3. Таймер

- Возможность задать длительность:
  - через пресеты (5 / 10 / 20 / 40 минут),
  - через кастомное поле (например, minutes input).
- Отображение:
  - крупный круговой прогресс‑бар (SVG/Canvas),
  - текст времени (осталось / прошло).
- Действия:
  - старт,
  - пауза,
  - перезапуск / завершение.
- Корректная работа при уводе приложения в фон:
  - таймер рассчитывает оставшееся время относительно системного времени.

### 5.4. Фоновые видео

- Компонент `VideoBackground`:
  - входные параметры:
    - `scene`: `welcome | picker | session`,
    - уровень затемнения/blur.
- Логика загрузки:
  - для десктопа и хорошего соединения:
    - `<video autoplay muted loop playsinline>` с постером,
    - форматы: `webm` + `mp4`.[web:9][web:12][web:14]
  - для мобильных / ограниченного трафика:
    - использование статичного постера вместо видео (детект по `navigator.connection` или по user agent), чтобы не перегружать сеть.[web:9][web:12][web:14]
- Требования к самим видео:
  - короткие (10–30 секунд),
  - зацикленные,
  - 720p, 24–25 fps, низкий битрейт,
  - без аудио‑дорожки (чтобы не конфликтовать с guided‑аудио).[web:9][web:12][web:14]

### 5.5. Работа с guided‑контентом

- На первом этапе:
  - статический JSON с описаниями медитаций;
  - локальные assets (аудио/видео).
- В перспективе:
  - вынос в API‑слой (REST/GraphQL) для обновляемого списка медитаций.

## 6. Нефункциональные требования

### 6.1. Производительность

- LCP (Largest Contentful Paint): 2–3 секунды на обычной сети.
- Вес initial‑загрузки (HTML+CSS+JS без тяжёлых медиа): желательно < 500–700 КБ.
- Фоновые видео и часть аудио загружать лениво:
  - подгрузка по переходу на соответствующий экран,
  - предварительный prefetch только для самых популярных/коротких медитаций.[web:9][web:12][web:14]

### 6.2. Адаптивность

- Основной таргет: мобильные телефоны (ширина ~360–430 px, портретная ориентация).
- Десктоп:
  - центрированный контент,
  - та же логика и размеры контролов.
- Все нажимаемые элементы ≥ 44×44 px (по рекомендациям по UX и доступности).[web:22][web:28]

### 6.3. Доступность

- Контраст текста и фона — минимум WCAG AA (4.5:1 для обычного текста).[web:22]
- Все изображения и видео имеют осмысленные `alt`/`aria-label`.
- Полноценная клавиатурная навигация:
  - `Tab` — переключение между элементами,
  - `Enter/Space` — активация кнопок.

## 7. Архитектура и стек

### 7.1. Высокоуровневая архитектура

- **UI-уровень**: SPA (Single Page Application), роутинг по состояниям.
- **PWA‑слой**:
  - manifest,
  - service worker.
- **Слой данных**:
  - v1: статические JSON/файлы медитаций,
  - v2: подключение к API‑бэкенду.

### 7.2. Рекомендуемый стек

- Фронтенд:
  - **React + TypeScript** или **Vue + TypeScript** (по выбору команды).
- Сборка:
  - **Vite** (поддержка PWA‑плагина).  
- Состояние:
  - глобальный store для текущей сессии (`MeditationSessionStore`).
- Стили:
  - Tailwind/CSS‑модули/SCSS — при условии использования единой дизайн‑системы.

### 7.3. Структура модулей

- Корневой компонент `AppShell`:
  - `Header` (логотип, настройки, переключатель темы),
  - `MainRouter` (роутинг по экранам).
- Экраны:
  - `WelcomeScreen`,
  - `PickerScreen`,
  - `SessionScreen`,
  - `EndScreen`.
- Компоненты:
  - `VideoBackground`,
  - `AudioPlayer`,
  - `Timer`,
  - `MeditationList` / `MeditationCard`,
  - `MoodSelector` (опционально).
- PWA:
  - `manifest.webmanifest`,
  - `serviceWorkerRegistration.ts`,
  - `sw.js` / `sw.ts`.

## 8. Данные и модели

### 8.1. Модель медитации

```ts
type MeditationType = 'audio' | 'video';

interface Meditation {
  id: string;
  type: MeditationType;
  title: string;
  description?: string;
  durationSeconds: number;
  mediaUrl: string;        // путь к аудио/видео
  backgroundScene?: 'ganga' | 'sea' | 'none';
  isOfflinePrecached?: boolean;
  language: 'en' | 'ru' | 'hi' | 'multi';
}
```

### 8.2. Модель сессии

```ts
type SessionMode = 'guided' | 'timer';

interface MeditationSession {
  mode: SessionMode;
  meditationId?: string;       // используется для guided
  targetDurationSeconds: number;
  startedAt: number | null;    // timestamp
  pausedAt: number | null;     // timestamp
  progressSeconds: number;     // обновляется таймером
  isCompleted: boolean;
}
```

## 9. PWA‑детали

### 9.1. Manifest

Минимальные поля:

- `name`: «Meditate with Sri Sri»
- `short_name`: «Sri Sri Meditate»
- `start_url`: `/` или `/welcome`
- `display`: `standalone`
- `background_color`, `theme_color`: из основной цветовой схемы
- `icons`: набор иконок разных размеров[web:16][web:18][web:19][web:20][web:30]

### 9.2. Service Worker

- Использовать Service Worker API для:
  - кеширования shell,
  - перехвата запросов к медиа и статикам.[web:21][web:27]
- Обработчики событий:
  - `install`: precache shell и базовый контент,
  - `activate`: очистка старых кешей,
  - `fetch`: стратегии кеширования (см. выше).

## 10. Локализация и тексты

### 10.1. Языки

- На старте: **английский** и **русский**.
- Вынести строки в JSON‑файлы:
  - `en.json`, `ru.json`, при необходимости другие.

### 10.2. Тональность

- Мягкая, доброжелательная, без агрессивных CTA.
- Примеры:
  - «Когда будете готовы, нажмите, чтобы начать».
  - «Если сегодня хочется короткой практики, выберите 5 минут».
